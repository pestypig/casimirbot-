# CFP-1 D07 Autoscale saturation cost stress — 2026-09-20

Program gate: G8 — Environment-harness release evaluation. CFP-1 remains active (`specified`), CFP-2/3 blocked. This is a cost sensitivity using a dated observed account configuration/rate, not a B/P/T marginal measurement, price selection, resource cap or financial-review return. The account-derived calculation is retained outside the public repository in `~/.codex/private-evidence/cfp1/2026-09-20-d07-autoscale-saturation-stress.md` (SHA-256 `ED24C49789CF6DFC2B406C8E6EA3BEE999BC61D8A3E055BF6DB4F5978E1DCC85`); this public record intentionally omits the private rate and derived account amounts.

The [observed Replit project view](2026-09-20-cfp1-replit-deployment-and-usage-recheck-115.md) showed a `4 vCPU / 8 GiB RAM / 1 Max` Autoscale configuration and connected production database. [Replit's billing guide](https://docs.replit.com/billing/deployment-pricing) defines compute units as 18 per CPU-second plus two per GB-second and describes billing during request work; [its database guide](https://docs.replit.com/billing/about-usage-based-billing) bills active database time and an additional five-minute window after the last request. Neither room-open time nor the deployment size is itself measured compute consumption.

The private stress assumes the one configured instance consumes its full CPU/memory allocation throughout the previously proposed **20 paid / two trial active room-hours**, with ten paying hosts and 30 trial starts in nonoverlapping intervals. It combines that conditional Autoscale load with the prior database active-time sensitivity and compares it with the existing $10 public Stripe-fee comparator. Under that adverse assumption, compute plus database leave only a narrow positive remainder before deployment, requests, egress, storage, identity, delivery, support, refunds, disputes, vendor tax, personal-baseline allocation and database idle tails; the 20%-of-gross contribution sensitivity fails before those omitted costs. The hypothetical $5 comparator fails on those two resource categories alone. This is **not** an estimate of typical utilization or proof that $10 cannot work. It shows that the earlier database-only pass does not bound the whole offer.

The next D07 evidence should measure, in matched B/P/T windows, billable CPU-seconds, GB-seconds and compute units **per sponsor-term active room-hour and outside counted room-hours**, plus requests, response bytes, database active minutes/overlap and storage growth. Compare a short action burst followed by idle room time with a sustained connected room; retain failed, duplicate and uncertain actions. Reconcile all provider units to project-specific usage for the same period and identify concurrent free-personal/development traffic. If live P/T measurement remains unavailable before CFP-1, the cost case needs sourced conservative bounds and specified future admission limits for each resource category, including what happens on exhaustion, rather than pricing room-hours and effect counts alone. CFP-3 then implements and tests those limits before a customer claim.
