The architecture coordinator provisionally treats processes running as the **same signed-in Windows user** as within P1's local device trust boundary. That is a visible security assumption, not a claim that signing or process labels prove which app invoked a bridge. Other users, remote executors and other devices must fail. The account/security owner must accept or revise that assumption before D02 is frozen. A stricter same-user adversary model would require enforceable caller authentication and might make this command-mode proposal inadequate.

The [new stdio qualification packet](../../../work-packets/eh-g8-cfp1-p1-stdio-local-bridge-qualification-v1.md) defines P1S-01–07, exact scope and downstream ownership. The earlier [HTTP helper packet](../../../work-packets/eh-g8-cfp1-p1-local-mcp-credential-and-recovery-contract-v1.md) is retained as a documented **conditional alternate**, not the default first build target. A theoretical stdio path is not installed acceptance. D02 still lacks the exact IPC security implementation, finite account/client-grant terms and ordinary-user proof; D07/D11/D12 and the overall CFP-1 exit remain open.
