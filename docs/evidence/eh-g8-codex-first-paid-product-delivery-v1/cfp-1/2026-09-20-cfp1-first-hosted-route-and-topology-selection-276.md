The initial action-inclusive trial and paid room use **one sponsoring host who also owns one installed connected program and paired player**, plus one separately verified invited guest on a second client device. The guest uses an authenticated first-party domain page for the owner-granted exact action, without a GPT/Codex account, connector installation or access to the host's model session. The host's local installation must independently confirm the room's bounded program share. The program share grants observation only; the effect requires a separate one-use exact owner pre-grant followed by the guest's deliberate request and current server/native checks. A guest-owned program, second installed node, existing-Codex-task binding or arbitrary member-owned action is not in this **initial** paid/trial action claim. Those broader G8/federation paths remain visible and require their own future acceptance.

An explicit eligible-host handoff can preserve the existing room but **immediately suspends** the original host-owned program share and new effects. If the original program owner remains or rejoins as a verified member, their signed local installation must reconfirm that exact share under the successor sponsor, and they must issue a fresh exact one-use grant. That sponsor≠program-owner continuation is a distinct D03/D07/D11/D12 and CFP-3/4 qualification, not silently included in the initial one-host-owned-program effect. Without it, room/history continuity must be presented as suspended action access with reviewed customer notice/remedy; no program grant or effect continuity transfers with payment.

The selected **CFP-3 implementation proposal** is the new `helix.hosted_room.*.v1` first-party create/inspect/invite/accept/program-share lifecycle under `/api/agi/hosted/v1`, followed by the [versioned owner-offer/guest-request/result API](../../../work-packets/eh-g8-cfp1-first-party-guest-action-api-contract-v1.md). The invitation is bound to one server-resolved verified invitee subject; a bearer code or matching email alone cannot join another account. Program sharing requires a separately authenticated signed-local confirmation, not the host's browser assertion. The existing `helix_room_create/list/inspect`, `helix_room_source_create/list` and `/realtime/rooms/join` are source comparators tied to the experimental one-model room and are deferred from this first customer claim. The conditional hosted `helix_minecraft_player_action` MCP entry is optional for a separately qualified guest reasoning client; it is not needed for the no-model guest baseline. The [operation overlay](../../../work-packets/eh-g8-cfp1-first-customer-operation-target-overlay-v1.md) records these distinctions without removing the existing source inventory or developer surface.
