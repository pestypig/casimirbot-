# CFP-1 individual Windows signing route screen — 2026-09-20

Program gate: **G8 — Environment-harness release evaluation**. CFP-1 remains active (`specified`); CFP-2/3 remain blocked. This is a bounded source and code screen for the owner's reported New York City individual-seller context, not a certificate application, provider selection, signed-build result or qualified D11 return.

| Source checked | Bounded finding | Release implication |
| --- | --- | --- |
| [Microsoft Windows code-signing options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options), checked 2026-09-20 | Microsoft describes Azure Artifact Signing for individual developers in the United States and Canada and estimates a basic service cost of about $9.99 per month. It warns that a new signed file can still receive a SmartScreen warning while reputation develops. | An LLC is not inherently required for the selected signed EXE route. Treat the quoted price as a dated planning input, not an account invoice, a guaranteed rate or SmartScreen acceptance. |
| [Microsoft Artifact Signing quickstart](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart), checked 2026-09-20 | Public Trust individual identity validation uses an Azure billing account of type Individual; its legal name and sold-to address must match government ID. The individual certificate displays city, state and country; street address is an optional profile field. | An owner-approved identity/privacy check must precede enrollment. The product brand cannot simply be substituted for the validated individual publisher name. Do not put identity documents or billing details in this repository. |
| [Microsoft Artifact Signing FAQ](https://learn.microsoft.com/en-us/azure/artifact-signing/faq), checked 2026-09-20 | The service does not support arbitrary certificate CN/O customization. | Freeze the verified publisher string before signing; compare it with the release workflow variable, Authenticode receipt, updater acceptance, installer UI and customer notices. |
| `apps/desktop/scripts/release-signing-config.cjs`, `.github/workflows/desktop-release.yml`, `apps/desktop/scripts/verify-release-artifacts.mjs` at the inspected Desktop checkout | The source has an Azure signing backend and CI login path using configured resource and `WINDOWS_PUBLISHER_NAME`; artifact verification compares the signature receipt with that publisher. | This is a code path, not proof of an Azure account, validated identity, configured CI permission, signed customer build or updater migration. |

CFP-1 should carry **individual Public Trust signing as a feasible conditional lane** for the first signed EXE. The owner must choose the signing provider and accept the certificate's verified-name visibility; D07 must include the actual recurring signing charge and any related CI/account cost as a fixed release cost. CFP-3 must prove an exact signed build, verified publisher and install/update behavior in the selected release cohort. If another provider or business identity is chosen, re-evaluate the name, cost and migration rules. The separate proposed GitHub artifact repository and kit remain unprovisioned. No credential, signing account, GitHub repository, Stripe state or public release was changed by this screen.
