**Recommended CFP-1 release rule:** define an explicit per-package first-customer allowlist tied to the selected C01–C15 artifact and D12 claim matrix. Until a package has a versioned rights/metadata/compatibility disposition and positive/denial fixture, do not publish it in the customer directory or admit it through generic directory pairing. Exclude the `fabric-player:0.4.0` directory package for the first cohort unless separately accepted; P03 bootstrap/JAR/manifest proof continues on its own route. The system-clock `1.0.0` package is a conditional C10 inclusion, not automatically approved by its built-in registration. Revisit Paper, Fabric sensor and synthetic fixture individually if a customer/developer claim later needs them.

**Proposed later fixtures:** DIR-01 GET returns exactly D12-accepted package IDs and no excluded/stale rows; DIR-02 valid direct start for an excluded ID fails with a stable typed reason before a session is created, and an older pending session cannot be approved or claimed after exclusion; DIR-03 accepted system-clock pairing/probe and its denial cases pass only if C10 is selected and rights-cleared; DIR-04 P03 bootstrap and selected personal action tests remain independent; DIR-05 a retained row with stale persisted descriptors/content hash fails or migrates under a reviewed version, never silently carrying source `approved` into a customer claim; DIR-06 an already claimed credential for a subsequently excluded package cannot poll, submit probe results or heartbeat after the policy cutover, while an independently approved package remains usable. Revoke/fence old credentials, devices and connector epochs or apply versioned eligibility at every device/probe admission before calling exclusion effective. These are CFP-1 acceptance designs, not present behavior.
