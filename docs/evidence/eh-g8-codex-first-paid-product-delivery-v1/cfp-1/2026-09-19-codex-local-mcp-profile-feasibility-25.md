## Verified client capability and current harness seam

Current [official OpenAI MCP documentation](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) states that the local ChatGPT desktop app, Codex CLI and IDE extension support configured MCP servers; local STDIO and Streamable HTTP are supported, and an HTTP example uses `http://localhost:3000/mcp`. Configuration is shared for the same Codex host. A local HTTP `http_headers_helper` can provide headers, subject to its documented credential precedence and refresh behavior. The hosted ChatGPT web surface does not read that local configuration. This supports **technical feasibility of a same-host client reaching a local MCP address**, not compatibility with CasimirBot's actual authorization, changing port, tool catalog or installed client.

## Recommended first qualification target

For the selected **Codex-first free personal** journey, qualify a same-host Streamable HTTP profile against the installed local `/mcp` service first. This is a technical priority, not an accepted customer route or an owner-selected entitlement. It matches the packaged local service and the documented local MCP client shape without making a hosted room subscription a prerequisite for basic personal tools. Preserve the remote tunnel as a separately qualified profile for clients outside the host machine and for hosted collaboration; do not claim that a web chat can reach `127.0.0.1` on the customer's computer.

Before CFP-2.ONBOARD/PUBLIC dispatch, the account/MCP/native owners must decide how the wizard installs or updates the local MCP configuration, discovers the current origin, obtains a narrowly scoped bearer without exporting the native session secret, and restores the exact connection after a port change. An `http_headers_helper` is a documented possible client mechanism, **not** a CasimirBot implementation or license to issue tokens without account consent. An STDIO shim is another possible local transport but would be new code and needs its own custody and lifecycle review. Do not choose between them merely from client documentation.

Acceptance must use one declared signed artifact and supported Codex client version: normal `user` account link; actual full `tools/list`; one selected owner-only source, observation, bounded rights-qualified effect and stop; wrong-account, stale URL, occupied preferred port, token expiry/revocation, restart and hosted-expiry cases. Distinguish a connection from a current grant and compare the coordination-only catalog. Test domain/identity outages separately; personal offline claims require actual installed evidence. Record the per-free-user operating cost of any required domain identity or tunnel service. A current local listener plus official client support is insufficient to mark the free personal loop accepted.
