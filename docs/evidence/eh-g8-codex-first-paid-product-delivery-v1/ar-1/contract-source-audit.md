## Findings that determine the next step

1. Three named humans require a capacity prerequisite. Both the shared constant and SQL constraints enforce two humans; invite and readiness logic also depend on two. Start with a synthetic deterministic three-human fixture. A fixture is not a live room and may not bypass production authorization.
2. Room membership, Live transport, Agent run binding, exact external task pairing, mission selection and program permission are different identities. Prove their joins explicitly.
3. Realtime worker admission and grounded-result relay exist. Existing correlation and interruption tests do not prove every shared-room mission-revision join. Treat stale worker output as evidence to recheck, never a delayed command.
4. The speaker resolver falls back from the active floor to the authenticated participant. Evaluate delayed transcripts, overlapping speakers, floor changes and wrong-speaker correction before claiming attribution.
5. API configuration is not runtime API access. Prior operator-dashboard observations of a project/key do not prove the running EXE/server uses that project or has access to the chosen models. No API call was made by AR-1.
6. Freeze server SDP exchange as the proposed AR-2 transport if supported by the tested build. Keep long-lived keys server/native-broker owned. The alternate ephemeral-client-credential path exists and must be identified if selected; do not describe it as secret-free.
7. Usage, payer attribution and retention require their own evidence. Queued deletion, public redaction, account eligibility or a development-credit balance cannot substitute for those checks.

## Consent, context, cost and data contract

- Each human separately permits microphone-to-room/model, transcript sharing, screen-to-model/thumbnail and model output as applicable. Account login, sponsorship and past consent cannot silently grant new media or program scope.
- Context is released only after exact room/session/thread/hash and current consent checks. Conversation history is untrusted observed data; quoted, negated, historical or future commands are not current authorization.
- Record worker evidence re-entry, completed solver/terminal authority, then relay acknowledgement and actual playback separately. A provider acknowledgement is not heard audio; an action receipt is not native success.
- Record provider usage per response/session with model/project/payer, input/output audio/text tokens where actually reported, cached usage if supplied, request IDs, retries, pricing version and reconciled cost. Missing data is unknown, never zero. Include separate reasoning worker usage.
- Before any paid call, choose a numeric API spend ceiling and enforce an available stop mechanism. The 700-credit AR-2 development allocation is not an API-dollar ceiling. Do not start an unmetered funded evaluation.
- Synthetic fixtures contain no real keys, private conversations or personal screens. Live evaluation requires a declared capture scope, storage location, access policy and expiry/deletion schedule before capture; record redaction and local deletion outcomes. Provider retention/deletion is separately verified or explicitly unknown.
- Revoke/leave stops new use of the revoked scope. Delete requests and local limits do not erase already processed provider data by assertion. Keep typed failure and teardown evidence, including unconfirmed cleanup.
- Reconnect may recover history, but must revalidate current consent, exact binding, producer epoch and grants. No authority can be restored merely by replaying history. Sponsor handoff requires an eligible accepting host; it cannot transfer another person's grants.
