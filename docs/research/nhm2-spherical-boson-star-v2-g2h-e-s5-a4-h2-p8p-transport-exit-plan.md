# P8P transport exit plan

This subordinate operational plan does not replace the canonical
[work program](./nhm2-spherical-boson-star-v2-work-program.md), change its active
gate, or reopen an exhausted attempt. It changes planning only. Historical
proposals, receipts and failures remain immutable. The
[R44 diagnosis](./nhm2-spherical-boson-star-v2-g2h-e-s5-a4-h2-p8p-r44-scp-diagnosis.md)
remains the evidence basis; a hidden trust prompt is a hypothesis, not a finding.

## Measure progress by resolved blockers

Primary milestones are: recover and authenticate the existing archive; identify
the build failure from its contents; reproduce and correct that failure; obtain
a separately authorized passing build fixture; then execute one separately
authorized P=1024 calibration and apply the unchanged P8Q yes/no rule.
Proposal counts and passing infrastructure tests are supporting work, not
substitutes for those milestones. No completion date or passing scientific
result is inferred from transport progress.

## 1. Local preflight before another paid restart

Use the installed SDK and actual transfer client, not only a mock of the
adapter. Test argument generation without a cloud API call: the exact source
and short destination must remain separate arguments; noninteractive and
verbose flags must survive SDK construction; force-connect must remain off.
Test actual client noninteractive failure behavior in an isolated local
fixture where feasible, with no real credential disclosure, trust-cache change
or external connection. If that cannot be tested within available scope,
record the missing coverage rather than claiming it passed.

Also verify bounded output capture, child-process termination, exclusive
evidence writes, cleanup after ambiguous start and explicit failure when stop
cannot be confirmed. Check the evidence retrieval path before depending on it
for a long computation. A local defect must be repaired and retested locally;
it is not a reason to start a VM to discover the same defect again.

Exit evidence must distinguish actual client tests, mocked orchestration
tests, source inspection and untested live assumptions. Do not call self-tests
an independent audit. No new cloud attempt may be proposed as ready while a
known local defect prevents bounded execution or useful diagnostic capture.

## 2. At most one separately authorized diagnostic attempt

Keep the same retained helper, archive and transport unless a subsequent
design review justifies a change. Freeze the exact procedure, limits and
inputs, then obtain separate authorization. This plan grants none.

The attempt must either retrieve the hash-bound archive or capture a specific
noninteractive error, then stop the helper and verify its status. Unknown or
mismatched host identity is a hard stop: no automatic acceptance, consent
injection, trust-cache mutation or use of a merely presented fingerprint as
authenticated trust. Do not extend runtime, switch resources or retry.

If the archive is not recovered, the next action is a transport-design review,
not another small live variation. This applies even if the attempt produces a
more specific error. Unconfirmed helper stop requires immediate operator
attention; it must not be left running while planning continues.

## 3. Mandatory review if retrieval still fails

Review all recovered error evidence together and identify the failed layer:
local client/argument handling, connection, authentication, host trust,
remote file access or local persistence. State what is proved and unknown.
Choose one stable design with a defensible trust source, observable bounded
failures and a locally testable transfer boundary. Do not change a VM, zone,
machine size, trust policy or budget merely to get another attempt underway.
Any needed scope expansion requires user approval. Produce no new execution
packet until the review explains why its change addresses the observed cause
and how it will avoid the previous failure class.

## 4. Return directly to the build and calibration

After recovery, validate archive paths, types and size bounds before local
inspection. Classify the fixture failure from authenticated logs, not exit
101 alone. Make only the supported candidate-neutral correction and test it
locally before a separately authorized build-only execution. Do not redesign
scientific mathematics to compensate for an infrastructure failure.

Once the fixture passes, return to the existing separately authorized P=1024
turnaround process and frozen P8Q decision. A calibration result may support
or reject resource-bounded proposal readiness; it is not a candidate solve,
proof, completed boson-star simulation or NHM2 physical viability claim.

## Handoff requirements

Every update should state the last evidence-producing milestone, the remaining
blocker, the next action and its authority requirement. Keep this plan's scope
separate from execution authorization. Preserve all evidence; cleanup or
resource deletion needs its own applicable authorization. Do not resume a
consumed one-attempt proposal under a generic continuation request.
