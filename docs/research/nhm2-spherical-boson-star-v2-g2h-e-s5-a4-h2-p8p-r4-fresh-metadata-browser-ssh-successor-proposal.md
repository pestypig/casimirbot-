failed with `Supplied fingerprint does not match current metadata fingerprint.`
It was stopped without Retry, upload, guest command, Docker installation, build
or numerical process.

Google Compute Engine documents that exact error as a VM metadata optimistic-
locking conflict: another process changed the instance metadata after the page
or client fetched it, so the update carried a stale metadata-content
fingerprint. The `instances.setMetadata` API describes this fingerprint as a
base64-encoded hash/version of the metadata contents and returns
`412 conditionNotMet` when it is stale. It is not an SSH host-key fingerprint.

Authoritative references:

- `https://docs.cloud.google.com/compute/docs/troubleshooting/troubleshooting-vm-update`;
- `https://docs.cloud.google.com/compute/docs/reference/rest/v1/instances/setMetadata`.

Google's first console resolution is to refresh the instance Details page
before the update. R4 applies only that resolution in a new versioned attempt.

state. Browser SSH may perform its ordinary transient SSH-key metadata update
