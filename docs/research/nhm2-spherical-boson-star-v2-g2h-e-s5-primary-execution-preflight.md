candidate-capable, identity-bound, and irreversibly guarded before any selected
member byte is evaluated? A `PASS` closes implementation/preexecution only. It
does not authorize or predict the scientific result.

## Frozen implementation order

1. Seal the checkpoint ABI, input inventory, environment allowlist, exact
   failure precedence, exclusive-root rule, record grammar, and self-test
   boundary before writing a candidate-capable entrypoint.
2. Implement the outer checkpoint guard and exercise it only with synthetic
   identities, corrupt records, forbidden-root fixtures, chronology fixtures,
   and an explicit dry-run that cannot enter the scientific dispatcher.
3. Implement all ordered primary classical duties `R2-C01..R2-C14`, including
   all four independent grids, validated terminal ball, global predicates,
   continuation, endpoint, mass agreement, and radial stability. `R2-C15`
   remains ineligible until a later independently authorized Rust result exists.
4. Implement primary quantum duties `R2-Q01..R2-Q05` behind the hard condition
   that every eligible classical duty passed. `R2-Q06` remains a later pair
   agreement duty.
5. Compile without invoking candidate mode in the frozen offline
   Arb/FLINT/GMP/MPFR lineage. Bind source, toolchain, dependency, image,
   executable, exact argv, environment, checkpoint, and absent root identities.
6. Independently replay all preflight fixtures and prove there is no path from
   self-test/dry-run to candidate ingress or output creation.
7. Run math validation, all required WARP tests, and Casimir certificate
   integrity. Only then may one inert versioned execution proposal be written.

## Hard chronology

The future checkpoint must reject before candidate ingress unless all of these
conditions hold in order:

1. canonical repository and fixed Linux runtime identities;
2. checkpoint self-identity and executable hash;
3. exact frozen contract/definition/builder/proposal hashes;
4. exact authorization-record grammar and token hash;
5. exact command and environment allowlist;
6. absent primary and independent candidate roots;
7. absent invocation/result/stdout/stderr ledger and fixed container name;
8. exclusive invocation persistence;
9. only then, selected-member ingress and the first scientific duty.

Any first persisted invocation, `PASS`, `FAIL`, or partial output would exhaust
the later proposal. S5 itself may not reach step 8 or 9.
