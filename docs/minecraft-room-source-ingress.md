# First-Party Minecraft Room Source Ingress

## Purpose

Once the full CasimirBot server is published at `https://casimirbot.com`, a
Minehut/Paper server or Fabric server/integrated-server host can send
observations directly to that deployment. A Cloudflare tunnel is not part of
the production path.

The source link is attached to a durable Shared Live Room, but it is not a
human invitation and it does not use the room's browser WebRTC data channel.
It is a separate, read-only server credential:

```text
Paper plugin or Fabric mod
  -> https://casimirbot.com/api/room-ingress/v1/bindings/<opaque-binding-id>
  -> trusted Minecraft adapter profile + durable manifest admission
  -> exact room/source/world/credential/producer-epoch admission
  -> protected world-event and environment-source services
  -> nonterminal observation-only evidence
  -> future authenticated room-aware Codex evidence re-entry
```

A static website is not enough. The published domain must route `/api` to this
Express server, and hosted deployments must use a shared Postgres
`DATABASE_URL`. The domain cannot expose a developer's private localhost;
local-only testing still needs a staging deployment or a temporary tunnel.

## Generate The Link

Sign in with a `developer` account, create or open a Shared Live Room, and use
**Generate link** under **Minecraft room source link**. Only the room owner can
create, rotate, list, or revoke source bindings.

For local and test environments, an experimental guest owner receives the same
read-only source-link control only while both the public Shared Live Rooms
experiment and guest room creation are enabled. Production additionally
requires `HELIX_GUEST_ROOM_SOURCE_INGRESS=1`. The grant is session-bound,
expires with the guest session, exposes only bound-room evidence and the
allowlisted Minecraft inventory probe, and never enables command execution.

The server returns a setup packet once:

```yaml
helix:
  endpoint: "https://casimirbot.com/api/room-ingress/v1/bindings/room_source_binding:..."
  bearer_token: "helix_room_src_..."
  source_id: "source:room-ingress:..."
  room_id: "shared_realtime_room:..."
  world_id: "minecraft:minehut:..."
  domain_adapter: "minecraft.paper_plugin.v1"
  execution_enabled: false
```

Paste those exact values into either
`plugins/HelixPaperSensor/config.yml` for Paper or
`config/helix-fabric-sensor.json` for Fabric, then enable the sensor. Both
bundled configurations are disabled by default. At startup the sensor refuses
a remote non-HTTPS endpoint and refuses the placeholder room-ingress
credential.
The bearer secret is shown once and only its SHA-256 hash and bounded prefix
are stored by CasimirBot. Do not put the secret in a URL, chat message, log,
screenshot, or source-control file.

The same lifecycle is available over authenticated management APIs:

```text
POST   /api/agi/realtime/rooms/:roomId/source-bindings
GET    /api/agi/realtime/rooms/:roomId/source-bindings
POST   /api/agi/realtime/rooms/:roomId/source-bindings/:bindingId/rotate
DELETE /api/agi/realtime/rooms/:roomId/source-bindings/:bindingId
```

Creation and rotation issue a short-lived, one-use browser
credential-delivery handle. Claiming that handle returns `token_value` and
`plugin_config` once; later list and management responses never return the raw
secret. Credentials default to seven days and
are capped at thirty days. The `source_id` is generated by the server in an
isolated room-ingress namespace; clients cannot select a legacy or
process-global source ID. Canonical environment/world services require the
exact server-created room-source admission for that namespace, and legacy
environment or world-event routes reject attempts to read or overwrite it.

## Public Source Routes

The generated endpoint is a base URL. The Paper plugin selects these routes:

```text
POST /world-events/batch
POST /manifest
POST /heartbeat
GET  /probes/pending
POST /probes/result
GET  /status
```

Every request requires the source bearer plus:

```text
X-Helix-Ingress-Version: 1
X-Helix-Request-Id: <uuid>
X-Helix-Producer-Epoch: <uuid for this plugin process>
X-Helix-Sequence: <unique positive integer from this producer epoch>
X-Helix-Sent-At: <UTC timestamp>
Digest: sha-256=<base64 SHA-256 of the raw body>
```

CasimirBot rejects missing, stale, replay-conflicting, out-of-order,
revoked, expired, or cross-binding requests. Sequence numbers remain unique
within a producer epoch, while monotonic delivery is enforced independently
for each route lane so concurrent manifest, heartbeat, event, and probe traffic
cannot reject a valid lower-numbered request merely because another route
finished first. Payload `room_id`, `source_id`, `world_id`, and
`domain_adapter` values cannot override the server-side binding. External
payloads cannot select an Ask thread, turn, session, trace, account, profile,
or room membership, including through nested metadata.

The raw `X-Helix-Request-Id` is retained only in the durable idempotency table.
Receipts, admissions, evidence references, journal records, debug projections,
and model-visible observations use a binding-scoped
`request_sha256:<sha256>` projection, where the digest input is UTF-8
`binding_id`, one zero byte, then the UTF-8 raw request ID. A request is
rejected before request-row or observation persistence when its authenticated
bearer, or a recognized source/chat claim-handle pattern, appears in the
request ID, producer epoch, or raw/parsed payload. Do not copy credentials into
actor labels, summaries, item names, evidence refs, or metadata.

The shared Minecraft connector client serializes its delivery queue, preserves
the same request ID,
producer epoch, sequence, timestamp, and digest across transport/5xx retries,
caps queued work, discards requests that become stale before delivery, and
coalesces periodic heartbeat/probe cycles while one is in flight. It validates
the complete receipt schema, the binding-scoped request digest,
binding/source/room/world identity, and nonanswer safety flags before treating
a 2xx response as admitted. It does not
repeat a typed
`room_source_request_outcome_unknown`; the next scheduler pass sends a fresh
current-state observation. Heartbeat, snapshot, and probe loops start only
after the manifest is admitted. The manifest is refreshed periodically so a
server restart can recover without restarting Minecraft. A 401, 403, or 410
stops the sender loops and leaves the exact typed error and request identity in
the plugin status.

## Minecraft Adapter Admission

Minecraft is the first enabled profile in the code-owned
`helix.environment_adapter_profile.v1` registry. Source creation accepts only a
registered Minecraft adapter identity paired with a `minecraft:*` world ID.
The manifest must then satisfy the profile's protocol, environment-state
modality, actor/inventory snapshot sections, read-only probe set, execution
prohibition, and payload ceilings.

The resulting durable `helix.environment_adapter_admission.v1` is bound to the
exact room, source, world, adapter, credential, producer epoch, profile
version/hash, and manifest hash. Heartbeats, events, and probe routes require
that admission. Credential rotation, revocation, expiry, owner-policy loss, or
room closure invalidates it. A restarted producer with a new epoch registers a
new manifest before sending observations.

The architecture and extension procedure are documented in
`docs/architecture/helix-environment-adapter-registry-v1.md`.

## Knowledge And Action Lanes

The room source solves authenticated current-world observation; it does not
replace game-mechanics retrieval. The existing `docs.search` gateway safely
returns bounded snippets and evidence refs and can locate a document from exact
body wording without its title. It is still primarily lexical: a natural
paraphrase can miss the correct document even when the mechanic is described in
the body.

Minecraft now declares the versioned
`mechanics.minecraft.java.v1` collection. A mechanics-scoped `docs.search`
request supplies that collection ID plus `game.minecraft.readonly.v1`; the
gateway resolves an allowlisted document scope and returns bounded nonterminal
evidence without requiring the document title. The current first collection is
intentionally small and should be expanded with mechanic-sized records:

- chunk by mechanic or rule, not only by file;
- carry game/version, mechanic id, aliases, preconditions, observable state,
  read-only probes, allowed actions, expected effects, failure modes, and source
  refs;
- combine lexical and semantic ranking, with the active room's exact game and
  adapter identity as retrieval filters;
- test exact wording, paraphrases, colloquial player language, underspecified
  follow-ups, corrections, and misleading near-neighbor mechanics;
- return bounded source excerpts as nonterminal evidence and require ordinary
  Codex evidence re-entry before an answer.

Future Minecraft command execution must be a separate admitted action
capability with its own allowlist, approval/idempotency policy, and typed result
receipt. Never add arbitrary command execution to this sensor bearer. The
command result must re-enter Codex before Helix can authorize a grounded
terminal answer.

## Agent And Safety Boundary

Room ingress owns transport authentication, identity, replay protection,
payload limits, evidence normalization, and acknowledgements. It does not own
reasoning or completion.

- Source receipts have `assistant_answer: false`,
  `answer_authority: false`, `terminal_eligible: false`, and
  `reentry_required: true`.
- Successful world-event ingress carries a server-created
  `helix.room_source_admission.v1` with exact
  binding/request-digest/room/source/world identity into the protected
  observation. The source payload cannot manufacture this admission.
- An authenticated Ask turn bound to the room can dispatch one of the admitted
  read-only capabilities. Its correlated current-turn observation must re-enter
  Codex before terminal synthesis; prior observations may be reused only as
  explicitly identified conversation evidence.
- A planner or panel action that merely queues/attaches a source remains
  `transport: unknown`, `freshness: unknown`, and `trust_level: unverified`.
  Only verified current-turn room-ingress evidence may promote source trust.
- An arriving event never starts an Ask turn, samples a model, selects a tool,
  writes a terminal answer, or speaks.
- The source may answer admitted read-only probes only.
- `execution_enabled` and `may_execute_live_actions` remain `false`.
- Probe results containing commands, side effects, or world mutation are
  rejected.
- Human room invitation codes and room source credentials are not
  interchangeable.

Generic Situation Room source lists, status projections, journal queries,
attach/replay actions, and thread-binding routes deliberately exclude the
reserved room-ingress namespace. They are not room-membership authorities and
must never enumerate or rebind a generated source. Ask continuation uses its
dedicated authenticated room-aware binding, verifies current room membership,
and preserves the exact server-created source admission. Transport acceptance
by itself is not answer authority.

## Deployment Configuration

Set one trusted base URL on the published server:

```text
CASIMIR_PUBLIC_BASE_URL=https://casimirbot.com
```

The canonical variable must be HTTPS in production. Legacy base-url variables
are accepted temporarily for compatibility, but new deployment configuration
should use `CASIMIR_PUBLIC_BASE_URL`.

Recommended production requirements:

- shared Postgres `DATABASE_URL`;
- TLS and `/api` routing on the same published origin;
- `TRUST_PROXY` configured to the actual proxy hop count;
- binding-aware global rate limiting plus the ingress per-binding limit;
- one deployment/state strategy for the existing process-local room signaling
  and environment runtime registries. Until those registries move to shared
  storage, use one instance or binding-aware sticky routing; autoscaled
  stateless routing is not release-safe;
- TURN configuration for reliable public Shared Live Room media, independently
  of this HTTPS sensor transport.

Closing the durable room or revoking its binding immediately stops new source
traffic. Rotation immediately revokes the previous credential. If the binding
owner loses the developer account policy or the `room_source_ingress` feature,
the next bearer admission revokes the binding and credential. Published base
URLs may include a deployment pathname; the generated endpoint remains the
source of truth.

## Typed Failure Guide

| HTTP    | Example error                                    | Meaning                                                                                                                                                                                                   |
| ------- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400     | `room_source_request_headers_invalid`            | Required ingress identity header is missing or malformed.                                                                                                                                                 |
| 400     | `environment_adapter_unknown`                    | The requested producer adapter has no trusted code-owned profile.                                                                                                                                         |
| 400     | `environment_adapter_identity_mismatch`          | Adapter, world, manifest domain, or bound identity crosses profile boundaries.                                                                                                                            |
| 400     | `environment_adapter_protocol_unsupported`       | The manifest protocol is not accepted by the selected profile.                                                                                                                                            |
| 400     | `environment_adapter_manifest_incompatible`      | Required modalities, sections, probes, or read-only policy are missing or exceeded.                                                                                                                       |
| 400     | `environment_adapter_observation_schema_invalid` | An observation or probe result does not match the profile's admitted schema.                                                                                                                              |
| 400     | `room_source_secret_exposure_rejected`           | Credential or claim material appeared in an ingress header or payload field; nothing from that request was persisted as observation evidence.                                                             |
| 401     | `room_source_credential_invalid`                 | Bearer is missing, wrong, or has been rotated.                                                                                                                                                            |
| 403     | `room_source_identity_mismatch`                  | Payload identity differs from the durable binding.                                                                                                                                                        |
| 403     | `room_source_owner_policy_revoked`               | The owner lost developer room-source policy; the binding was revoked.                                                                                                                                     |
| 408     | `room_source_request_stale`                      | Transport or live event timestamp is outside its window.                                                                                                                                                  |
| 409     | `room_source_idempotency_conflict`               | Request ID or producer sequence was reused for different content.                                                                                                                                         |
| 409     | `environment_adapter_admission_required`         | Register a compatible manifest for this exact credential and producer epoch before sending observations.                                                                                                  |
| 409     | `environment_adapter_contract_changed`           | The durable admission names an obsolete profile version/hash and must be re-admitted.                                                                                                                     |
| 409/503 | `room_source_request_outcome_unknown`            | A prior operation may have applied but its durable receipt cannot be proven. Do not retry the same mutation or assume failure; send a fresh current-state observation with a new request ID and sequence. |
| 410     | `room_source_binding_closed`                     | The attached room was closed.                                                                                                                                                                             |
| 413     | `room_source_payload_too_large`                  | Reduce snapshot/batch size.                                                                                                                                                                               |
| 429     | `room_source_rate_limited`                       | Back off before sending more source traffic.                                                                                                                                                              |

These are accurate source failures, not assistant answers. Clients should
surface them as diagnostics and must not fall back to stale world state.
