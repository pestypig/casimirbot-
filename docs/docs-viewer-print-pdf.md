# Docs Viewer print-PDF export

## Purpose

The Docs Viewer can create a print-ready PDF from the exact Markdown source
currently loaded in the panel. The export path is intended for long technical
papers with KaTeX equations, tables, code, and local document images.

This is a render-integrity workflow. A passing receipt means the PDF parsed,
the browser reported no broken images, KaTeX errors, or horizontal overflow,
and the recorded equation and table counts were emitted. It does not certify
the document's scientific or factual claims.

## Operator flow

1. Open a canonical document, or sign in and open a private Research Library document, in Docs
   Viewer.
2. Select **Download PDF**.
3. Wait for the success status, which includes the validated page count.

The browser downloads the returned artifact only after it receives a valid
render receipt. Failed or partial responses are not downloaded as PDFs.

## Runtime contract

- Endpoint: `POST /api/docs/print-pdf`
- Request schema: `docs_print_pdf/1`
- Account boundary: available to signed-out visitors, public users, and developers
- Input ceiling: 1,500,000 Markdown characters
- Renderer: headless Playwright Chromium
- Paper format: US Letter
- Network policy: blocked during rendering
- Remote images: omitted with a visible placeholder
- Local images: embedded as bounded data URIs
- Raw HTML: escaped except for a small print-safe allowlist; Markdown comments
  are suppressed
- Concurrent renders: one server render at a time

Every successful response includes:

- PDF SHA-256
- page count
- equation count
- table count
- `X-Docs-PDF-Validation: pass`

## Validation gates

The server fails closed when any of these checks fails:

- the request does not match the strict schema;
- Chromium is unavailable;
- KaTeX emits an error node;
- an embedded image is broken;
- a non-SVG print element exceeds the page width;
- the result is not a valid multi-page PDF.

The service reopens the generated bytes with `pdfjs-dist` before returning
them. The client independently checks the content type, validation marker, and
SHA-256 header shape before starting a download.

## Installation and release notes

`playwright` is a production dependency because PDF generation runs on the
server. Install the matching Chromium runtime once on a new workstation or
deployment:

```text
npx playwright install chromium
```

The UI and server capability are both governed by the
`docs_viewer_print_pdf_export` account feature flag. It is enabled in the
default public `user` policy as well as the `developer` policy. An explicitly
locked or flag-disabled custom policy still fails closed.

## Focused verification

```text
npx vitest run server/__tests__/docs-print-pdf.service.test.ts server/__tests__/docs-print-pdf.route.test.ts client/src/lib/docs/__tests__/docsPrintPdfClient.spec.ts client/src/components/__tests__/doc-viewer-taxonomy-ui.spec.tsx server/__tests__/account-session-panel.test.ts --pool=forks
```

The service test performs a real Chromium PDF render. For release inspection,
also export a representative full paper, render selected pages to PNG with
Poppler, and visually inspect the cover, contents, equations, tables, section
transitions, and final page.
