Source `approved` metadata is not a CFP-1 rights or customer-support disposition.

Before dispatch, D12 must freeze a versioned row for each of `minecraft.paper:1.1.0`, `minecraft.fabric:0.3.0`, `minecraft.fabric-player:0.4.0`, `synthetic.fixture:1.0.0` and `system.clock:1.0.0`: exact package-version ID, public listing treatment, generic pairing/device treatment, persisted metadata/hash rule, rights and notice disposition, supported profile, customer/developer sentence, positive/denial fixtures and cutover behavior. The [provisional first-cohort matrix](eh-g8-cfp1-public-directory-first-cohort-scope-v1.md) excludes Paper, Fabric sensor, Fabric player and synthetic fixture from public generic directory/device use; it conditionally includes system-clock only after C10 rights, metadata and clean external-kit probe acceptance. The separately reviewed P03 player and sensor bootstrap paths remain independent. These choices are release-policy inputs, not implemented admission or final D12 acceptance.

The connector service owner should implement one reviewed server-side release-policy source of truth, keyed by immutable package ID/version and policy revision, rather than treating a filtered GET as admission. Candidate owned surfaces are `server/services/environment-connectors/directory/index.ts`, `server/services/environment-connectors/pairing/service.ts`, the public connector route, a narrowly scoped release-policy module and focused tests. Freeze actual file ownership with the C10 kit and CFP-2 connector owners before dispatch. The policy must cover GET projection, direct start, pending approval/claim, active device/probe admission and withdrawal. Existing installations, sessions, device credentials, bindings and connector epochs need a cutover procedure: deny an excluded package at subsequent transport admission or revoke/fence it durably before describing exclusion as effective. Preserve the authenticated developer superset through an explicit internal/developer surface where appropriate; do not expose evaluation packages to anonymous/public users merely to preserve developer access. Avoid deleting code-owned built-ins or database rows as an unreviewed shortcut, since seeding can recreate rows and retained devices may remain active.
