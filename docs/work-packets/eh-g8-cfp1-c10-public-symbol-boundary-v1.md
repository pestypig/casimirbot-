## Artifact boundary to select

The first output should be a versioned, independently installable wire artifact plus the reviewed TypeScript/Java helper, template, examples and conformance fixture that use it. It should publish **generated or deliberately assembled declarations and schemas for exactly the owner-selected symbols**, not copy the four source modules and their transitive imports by default. The current eleven-file kit is in-repository source, not that artifact. Package name, version, license, notices, distribution channel, supported endpoint/client versions and update rule remain owner decisions. The separate Device Check plugin and verifier packages are not implicitly included.

The exported-name ledger is only the first boundary. The selected schemas still refer to `shared/helix-environment-state-snapshot.ts` and `shared/helix-environment-sensor-scope.ts`; the TypeScript helper uses `zod` and Node `crypto`. A compiler-generated declaration may expose another type or import even when its top-level name is absent from the ledger. The package builder must trace and review **all transitive declaration, runtime, JSON and license bytes**. It must either close selected types inside reviewed generated output or declare public dependencies with version/notice terms. It must not solve missing imports by copying private shared modules wholesale or hand-maintaining a divergent wire contract.

## Later implementation rejection checks

1. Reserve an immutable source commit and selected CSV revision. Generate the package twice; compare file hashes and an export inventory. Reject any missing selected name, extra deferred name, private path import, unresolved dependency or undeclared runtime requirement.
2. Compare emitted JSON/declarations and schema behavior with the corresponding canonical runtime contracts at that source commit. Reject version or validation drift. Keep any deliberate compatibility transform explicit and tested.
3. From a clean checkout **without** the private repository, install the documented package and dependencies; compile the TypeScript starter with a declared supported Node version, compile the Java helper with JDK 21, and run the probe conformance fixture.
4. As an independent developer, complete the documented pairing and one bounded read-only probe against a supported endpoint. Verify denied scope, expired pairing, duplicate/replayed submission and unavailable endpoint results as typed failures. Do not infer hosted collaboration or mutating capability from this probe.
5. Extract the actual release archive and review its files, bundled dependencies, licenses, notices, examples, README, branding and claims against C10 and the rights disposition. Reject unexpected source or asset inclusion.
