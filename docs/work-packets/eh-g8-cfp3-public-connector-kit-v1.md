# CFP-3 public connector kit candidate v1

This is the missing C10 implementation handoff for the [first-customer component sheet](eh-g8-cfp1-first-customer-component-decision-sheet-v1.md) and [claim FC-08](eh-g8-cfp1-first-customer-claim-freeze-worksheet-v1.md). It is **non-dispatchable** while CFP-1 remains active and qualified rights review is open. The current eleven-file `connectors/environment/` tree is in-repository source. Its contract entrypoint re-exports 71 names from four shared modules; the [owner-selected 43/28 symbol target](eh-g8-cfp1-c10-public-symbol-boundary-v1.md) and [artifact direction](eh-g8-cfp1-c10-public-kit-artifact-decision-v1.md) constrain the first output but grant no public API license. The TypeScript helper imports repository-relative contract code and Node `crypto`; selected schemas use `zod` and shared state/sensor types. There is no standalone package manifest/export pipeline today.

The registered system-clock example additionally depends on the separate [public directory/admission handoff](eh-g8-cfp3-public-connector-directory-admission-v1.md). The kit's clean build cannot prove a customer-visible package row, direct pairing eligibility or old-credential cutover; DIR-01–06 must be accepted with the selected C10 row before FC-08 is claimed.

## Admission inputs and file ownership

Before dispatch, the CFP-1 coordinator verifies control of the proposed dedicated GitHub release channel and package scope, then freezes the owner-selected name-by-name API ledger, versioned package ID, supported Node/TypeScript/JDK versions, endpoint/client profile, read-only claim, license/notice inventory, compatibility policy and exact CFP-3 file manifest. The planning target is a `0.1.0` archive/installable tarball without an npm-registry commitment; wire `v1` and registered system-clock connector `1.0.0` are distinct versions. A qualified reviewer disposes the six shared-source dependency closure, generated declarations/JSON, `zod`, helper and Java dependencies, examples, branding, prior-publication grants and every packaged byte. No builder can infer rights from an MIT declaration on the separate verifier SDK/CLI.

Proposed primary writer owns `connectors/environment/**`, its new package descriptor/build configuration, export generator, standalone conformance fixture and developer guide. The canonical shared modules remain owned by their existing contract/adapter owners; this packet may consume them but may not silently refactor runtime authority or change the adapter registry. `CFP-3.DISTRIBUTION` owns the chosen public archive/feed, download metadata, notice access and update integration after this packet emits a reviewed immutable artifact. Freeze any shared script/workflow ownership sequentially; do not have both packets edit the same release file concurrently. The public API stays generated or deliberately assembled from canonical selected schemas, never a hand-edited divergent copy.

## Implementation and rejection contract

1. Build a versioned package from one immutable source commit and selected allowlist. Emit declarations, runtime schemas/JSON where selected, the reviewed TypeScript helper, Java helper, template, synthetic/system-clock examples, conformance fixture, README, license and notices. Include only the selected files and dependencies; do not copy all four wildcard modules or the private server graph by default.
2. Record input file hashes, package file hashes, SBOM/package-origin report, dependency versions, build command, release channel and compatibility rule. Run the build twice from clean inputs; non-reproducible bytes require a documented reproducibility exception and artifact-specific rights review, not a silent pass.
3. Compare public exports exactly against the frozen ledger. Reject a missing selected symbol, extra deferred symbol, Minecraft-specific export not separately approved, unresolved declaration/runtime import, private path/credential, undeclared `zod` or Node/JDK requirement, schema-version mismatch or differing canonical validation behavior. Trace **transitive** declaration and runtime dependencies, including state-snapshot and sensor-scope types; top-level export parity alone is insufficient.
4. Run TypeScript and Java compilation from a clean external directory with no CasimirBot checkout, workspace alias, ambient secret or developer launcher. Use a standalone non-game fixture; the existing test's Minecraft manifest import is not suitable for this public claim. Exercise heartbeat receipt validation, including the currently missing mock `command_execution` field. Run probe conformance against the package, then have a developer who did not author it follow the published guide to pair the **registered system-clock package** with a supported endpoint and complete one non-game read-only probe. Record all undocumented steps and manual intervention. Repeat wrong identity/scope, expired pairing, duplicate or replayed submission, incompatible version, unavailable endpoint and unknown package; each returns the documented typed failure without cross-owner data or an effect. Current pairing accepts only built-in package versions; this proof cannot claim arbitrary third-party registration.
5. Extract the **exact proposed public archive** and review its bytes, notices, README, branding and claims against the selected C10 treatment and rights disposition. Test package removal or version mismatch without leaving usable stale connector authority. The in-repository `helix:environment-connectors:live-acceptance` script may be regression evidence, but it cannot replace this independent-package proof.

The implementation packet must add named package, export-parity, clean-install and conformance commands before execution; this candidate does not assert those commands exist. Record each command's input revision, output hash, expected/actual result and first failure. A package that compiles but cannot pair from the published instructions fails FC-08. A successful system-clock probe supports only a bounded read-only starter claim. Any action-capable public developer interface or cross-program hosted claim needs a separately admitted contract and the [DEV-01–06 evidence](../architecture/casimirbot-developer-platform-product-contract-v1.md), including a materially different reviewed program.

## Handoff and stage fence

The CFP-3.DEVELOPER-KIT reviewer checks source diff, exported-name and transitive-byte inventories, license/notice return, schema parity, clean-room build, independent-user probe and negative cases. CFP-3.DISTRIBUTION then proves access from the selected public channel without membership in private source, exact version/notice availability and update or withdrawal behavior. CFP-4/5 repeat only claims actually selected for customer copy; CFP-6 decides release wording. Neither packet may call a probe-only starter an action SDK or claim that a package build has qualified the broader paid platform.
