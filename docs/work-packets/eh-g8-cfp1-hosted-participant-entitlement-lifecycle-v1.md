## Independent authority axes

Keep the following axes separate in storage, API decisions and UI. There is no single `room_ready` or `subscriber_can_act` bit:

| Axis | What it establishes | What it never establishes |
| --- | --- | --- |
| Verified CasimirBot account/session | Which person is acting; Google or another verified login resolves the stable internal account through the reviewed link flow. | Developer status, payment, external Codex account ownership or a player grant. |
| Supported external client connection | Which authenticated MCP client can request which personal tools. | Permission to steer an existing closed task or use another person's provider subscription. |
| Hosted subscription and service admission | Whether the selected billing owner may sponsor an eligible hosted feature within its current term and capacity. | Room membership, AI processing consent, model account sharing or environment action authority. |
| Room membership and role | Which authenticated person joined which room and may see its permitted products. | Ownership of a contributed node, connector credential or another member's data. |
| Participant processing consent | Which of the participant's media/context may reach which room or model surface. | Approval for game or other program effects. |
| Owner program grant and current effect lease | The exact node, environment, subject, capability, limits and duration a program owner permits; the local connector confirms current effect authority. | Renewal merely because subscription, room or historical goal state survives. |
| Principal binding and delivery | Which one exact external reasoning task, if supported, can receive a room proposal and whether it actually did. | An action result, continued supervision or a second mission writer. |

The predicate depends on the requested operation. Room creation needs a verified
account and the selected sponsor's hosted-create eligibility; no room membership
exists yet. Joining needs verified participant identity, a current invitation,
the room's eligible service state and the selected guest/seat rule; it does not
require a program grant. Room-only reads and management need current membership,
role and applicable service admission. A shared-program read or effect adds the
program owner's exact grant. Effects also require client/source identity,
consent, freshness, a current lease and native effect policy. The payer lookup
resolves the selected host's verified trial or paid term; an invited guest does
not need their own purchase merely to join. The owner selected explicit handoff
to another eligible host on sponsor loss, but no automatic transfer; until a
reviewed handoff succeeds, new hosted operations fail closed. Free personal MCP
access evaluates its own identity, client, target and
consent checks without a hosted-payment predicate. Stop, revoke and account
recovery remain reachable under their own authenticated safety rules even after
hosted eligibility ends.

The [handoff protocol proposal](eh-g8-cfp1-host-handoff-protocol-v1.md) documents
why the current fixed owner/slot, source-credential and media-host checks cannot
be switched by a billing-field update. Its lost-host recovery authorization is
still an owner decision, not a current room operation.

## Proposed customer transitions to freeze

The [trial/account source map](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-19-trial-account-identity-source-map-37.md) adds an O-05/O-07 prerequisite to these transitions. The owner [selected that a used trial stays used after deletion and return with the same verified sign-in identity](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-19-trial-reuse-owner-selection-39.md). A trial start must be an idempotent authenticated operation against the verified sponsor identity, with one authoritative start/end and eligibility revision under concurrent requests. The account owner must freeze how minimum necessary consumed-trial evidence survives permitted deletion/re-enrollment and provider relinking, and how that treatment is disclosed and retained. A same-email account is not automatically the same identity; a deleted account or reinstalled node cannot restore membership or a grant through stale state. The selected return rule is not implemented by the present profile-keyed sandbox credit ledger.

The [provisional trial capacity and effect targets](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-19-provisional-hosted-trial-limits-owner-selection-48.md) are one active room, one invited guest, one connected program and ten verified bounded effects per sponsoring host during seven days. Store the aggregate count against that verified sponsor/trial identity, not a room, browser, device or connector installation. Reserve and settle concurrently attempted effects so at most ten native postconditions can be committed; release rejected/failed/duplicate reservations without giving an uncertain effect a second execution. Handoff must re-evaluate the successor's own eligibility and remaining allowance; no predecessor trial time or quota transfers merely because the room survives. Exact unit, handoff counter semantics and final values remain subject to cost/installed review.

The [explicit-activation start proposal](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-19-hosted-trial-start-proposal-50.md) is pending owner selection. If selected, the account service writes one authoritative seven-day interval and revision after a clear host action; concurrent starts and uncertain responses resolve to the same record. Login, download, room setup and free personal use would not consume the trial. The proposal requires an accepted, rights-cleared hosted action to be available before activation is offered.

These behaviors are policy proposals for the selected offer, not a claim that current handlers implement them. Each dependent packet must freeze the effective clock and limit values before tests.

CFP-2.PUBLIC/ONBOARD own ordinary-user personal reachability, verified account linking and never-subscribed/expired-hosted regressions. CFP-3.COMMERCE owns authoritative subscription events and portal; CFP-3.LICENSE owns only the hosted grant and its server/installed admission boundary; room owners retain membership, consent and source binding; connector owners retain native effect authority. Use existing DOM-01–07, ENT-01–08, COLLAB-01–06 and DIST-06 cases; do not invent a weaker parallel acceptance scale. Rights, signed-distribution and canonical G8 prerequisites remain separate gates.
