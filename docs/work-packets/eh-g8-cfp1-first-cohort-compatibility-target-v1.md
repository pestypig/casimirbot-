The first-cohort acceptance specification must carry these cases into [FC-02](eh-g8-cfp1-first-customer-claim-freeze-worksheet-v1.md) and conditional FC-04. A positive P1 case uses the exact Codex package and selected Windows baseline with a signed CasimirBot evaluation build, ordinary `user` account, current device grant, actual personal `tools/list`, a selected read, one rights-qualified bounded effect, result re-entry, stop/revoke and restart recovery. A Minecraft-positive case additionally proves the exact loaded Fabric tuple, manifest and native postcondition under ID-01/03–06 and the selected operation subcase. Neither a catalog entry nor a request enqueue is an effect.

Negative cases must reject or clearly mark unqualified: a different Codex build; unsupported Windows baseline; wrong/switching local account or stale device grant; incompatible Minecraft, Loader, API or Java version; stale or substituted JAR/nested core; manifest/adapter/capability drift; and an excluded generic-directory package. A failed compatibility or identity check must not silently switch to a developer route, a different connector, a provider API key or a paid entitlement. Stop/revoke and the independently eligible free personal tools remain reachable under their own policy. Record typed reasons and preserve the failed trace.

**Version-change rule:** If Codex auto-updates before CFP-2's run, CFP-1 amends this selected target and the fixture manifest with the newly observed exact package version, followed by independent review, before treating the new build as the cohort. A passed older build does not confer support on a newer build. The same rule applies to Windows build-family, game, Fabric, Java, JAR and adapter changes. D12 may approve only the tested version/profile wording; an expanded range needs representative installed proof and a reviewed compatibility policy. The broader Codex-client, Windows and game support roadmap stays open.

This target resolves the **which versions, artifact identity and hardware floor to qualify first** selection within D01/D02. It does not claim that the reserved build exists or that the qualification floor is a final consumer minimum. D02 configured-provider and installed account proof, D03 rights, D07 price/cost, D11 returns, D12 final claims and the parent CFP-1 exit remain open. CFP-2/3 remain blocked until the canonical work program admits them.
