## Objective

Connect already-protected Minecraft situation digests to the existing Stage
Play live-source mailbox. The bridge emits nonterminal evidence only when a
fresh, provenance-valid digest represents a meaningful semantic change. Routine
equivalent position/snapshot traffic updates the local baseline without waking
Runtime Codex.

The accepted chain is:

```text
protected room-source event batch
→ canonical environment situation digest
→ semantic-change/coalescing decision
→ Stage Play processed-mail packet
→ nonterminal wake admission
→ current-turn mailbox observation
→ Runtime Codex interpretation and material replan
→ Helix terminal eligibility
→ matching text and applicable voice presentation
```

## Identity contract

Every Minecraft mail item carries the exact room source binding, room, source,
world, producer epoch, subject binding when present, digest id/hash, and latest
event sequence. A background environment wake does not invent a speaking
participant. Participant-to-player authority is resolved later from the room
and subject binding by the existing Ask admission path.

## Wake-selection contract

- A first routine snapshot with no active hazard establishes a baseline.
- Repeated equivalent semantic state is coalesced.
- Position-only movement does not wake Runtime Codex.
- A newly active hazard, viability change, inventory milestone, focus/target
  change, workflow transition, advancement, route invalidation, or other
  non-routine admitted event may enqueue semantic mail.
- Stale, provenance-invalid, identity-mismatched, or non-monotonic digests fail
  with stable typed reasons and never enter the mailbox.
- Mail, packets, wake requests, decisions, receipts, and UI projections remain
  observations. Only the completed Runtime Codex solver path may answer.

## Acceptance order

1. Deterministically verify digest identity, semantic selection, coalescing,

2. Verify one processed packet and wake lifecycle without a live provider.
3. Run one natural keyed Minecraft event journey through the real Ask route.
4. Compare exact digest, mail, packet, wake, Ask turn, observation, candidate,
   terminal, and visible identities at the first divergence.
5. Retain G1, G2, G3, `/helix ask`, and applicable text/voice regressions.
