# CFP-1 public interface and source boundary v1

The selected offer keeps the supported personal MCP experience free and charges for maintained hosted collaboration. Neither price nor repository visibility decides source rights. This packet turns the [developer-platform direction](../architecture/casimirbot-developer-platform-product-contract-v1.md) and R-PUBLIC-01/R-OWN-01 in the [component rights matrix](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/rights-draft-2026-09-06/rights-component-matrix.md) into a file-level publication decision. It proposes a separate, usable public interoperability artifact while treating the main implementation as a **future private candidate only after rights review**. Prior published grants and third-party terms remain in force for their covered material. No current file is relicensed or hidden by this packet.

The [MIT license text](https://opensource.org/license/mit) allows recipients to distribute covered copies subject to its notice condition, and [GitHub's visibility documentation](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility) says existing public forks stay public when a public repository becomes private. These general facts do not establish which CasimirBot files were actually licensed or who holds rights in later contributions; R-OWN-01 must resolve that per component.

The [2026-09-19 publication/provenance checkpoint](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-19-source-publication-provenance-14.md) records that the connected GitHub repository currently reports public visibility and that the earliest inspected root manifest already declared MIT. It also distinguishes six Git author strings from verified contributors or rights holders. This is a current-state input to the proposed split, not permission to change visibility or relicense source.
The later [targeted path-authorship crosswalk](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-19-rights-path-authorship-crosswalk-28.md) maps author strings to the proposed main-product and public-artifact path cohorts. Its commit counts identify which ownership records to seek; they are not proof of assignment or rights to relicense.
The [owner's subsequent authorship statement](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-19-first-party-authorship-owner-attestation-29.md) says the named identities and product work are theirs. It is an owner assertion awaiting file-level contribution, agreement, import and prior-publication evidence; the proposed private/public boundary still needs a qualified rights disposition.

## Decision and downstream acceptance

The product owner must select the exact public artifact IDs, repository/package channels, version and supported probe scope; decide whether Device Check and verifier packages are published alongside or separately; and approve a file-level include/exclude list after the rights reviewer identifies prior licenses, contributors and required notices. The owner must also select the main source-visibility transition only after customer binary/update access no longer depends on membership in that source repository. The [domain/delivery plan](../architecture/casimirbot-domain-accounts-and-delivery-plan-v1.md) and [CFP-3 distribution packet](eh-g8-cfp3-distribution-migration-v1.md) own the corresponding forward migration.

The dependent developer-kit implementation packet must name the export generator, exact shared-schema allowlist, package manifest, license/notice files, TypeScript and JDK build, clean-room install fixture, schema parity test, version/deprecation rule, supported endpoint, negative cross-owner/scope cases and DEV-01–06 evidence owners. CFP-1 prepares that handoff; it does not dispatch it. An independent developer's successful read-only probe would qualify only the read slice of DEV-01/02, while generic mutation and hosted reuse still require separate implementation and acceptance.

R-PUBLIC-01 and R-OWN-01 remain open. This proposed split protects interoperability without asserting that the current kit is already standalone, that an entire historic MIT tree can become proprietary, or that source publication alone grants runtime authority.
