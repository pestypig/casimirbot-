## What current source does and does not establish

At source HEAD `256554ca2637b2978a83616d9f9670069fdfd8c4`, `shared/helix-shared-realtime-room.ts` limits a room to two participants. The base `user` policy locks shared rooms; the public-room experiment requires both an enabled server setting and a stored account policy already enrolled for rooms, while nondeveloper source ingress has additional conditions. These are experimental policy checks, not subscription admission or proof of free personal reachability. `shared/helix-billing-entitlement.ts` exposes a sandbox credit-oriented entitlement with `starter_monthly` and prepaid-credit checkout targets. Existing sandbox event handling is reuse material, but it is not a hosted-room SKU or proof of the reported $5/$10 Stripe Price objects. The [current payment-to-Minecraft-effect source map](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-19-payment-to-minecraft-effect-source-map-15.md) traces how room account policy gates the inspected player-action path while billing remains separate. The later [guest-action source review](eh-g8-cfp1-first-paid-shared-action-candidate-v1.md) adds a separate blocker: the action broker denies a guest acting on another member's paired player, and authority setup requires the room owner to own that player. The [September 8 code/deployment audit](eh-g8-cfp1-code-deployment-alignment-audit-v1.md) observed one Replit Autoscale deployment and a production database connection label; it did not measure per-customer cost, actual database authority, live Stripe configuration or paid-room throughput. The current two-person cap happens to match the provisional host-plus-one-guest trial target, but does not enforce trial eligibility, establish a paid-tier limit or prove three-person acceptance.
