# C10 first public kit artifact decision v1

The owner-selected first target is the [43 included / 28 deferred symbol ledger](eh-g8-cfp1-c10-public-symbol-boundary-v1.md). The product direction is a **separate public, read-only developer starter**, while the CasimirBot service source stays under its own visibility decision. This packet selects an **archive-first** delivery target: a dedicated `pestypig/casimirbot-connector-kit` GitHub repository with a versioned release asset, and an installable TypeScript tarball named `@casimirbot/environment-connector-kit` at initial kit version `0.1.0`. Those names are planning identifiers, **not verified repository or npm-scope ownership, created assets, or a promise to publish to npm**. Before CFP-3 dispatch, verify account/scope control and choose a replacement identifier if either is unavailable. The wire contract remains `v1`; the currently registered system-clock connector package is separately versioned `com.casimirbot.system.clock:1.0.0`. A kit-version change must not silently change either contract or registered connector identity.

The [authenticated GitHub channel inventory](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-20-cfp1-authenticated-github-channel-inventory-148.md) found the source repository public/admin-controlled by the connected owner, but the proposed kit repository returned 404 and was absent from that connection's accessible-repository list. This is no name reservation, created package or publication.

The release should be a **generated or deliberately assembled output from canonical source at one pinned commit**, with a manifest that lists every packaged path and hash. The initial archive may contain only the following reviewed outputs:

The source inputs are **not** a release-file allowlist. The current eleven-file tree has no standalone package descriptor/export pipeline and cannot be published by copying its directory. The six shared-source modules are rights and dependency inputs, including state-snapshot and sensor-scope closure, but only selected generated public output may enter the archive. Defer all adapter-profile exports, Minecraft-specific exports, Device Check plugin, verifier packages, internal launcher material and every mutating action helper. The root `package.json` MIT field and a separate verifier package's license are not the C10 package rights decision; the first-party/prior-publication treatment and `zod` notice require a qualified return.

**First claim boundary:** an independent developer can install the archive without private source, pair against a supported endpoint using a **registered** system-clock starter, and complete a bounded read-only probe. Current pairing calls `readBuiltinEnvironmentConnectorPackage`; an arbitrary third-party package is rejected as `pairing_package_unknown`. This kit therefore does **not** promise open third-party registration or a developer action ecosystem. That future platform step needs an admitted registry, trust, distribution, permission and review design under DEV-01–06.

The [public-directory scope audit](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-20-cfp1-public-directory-package-scope-audit-178.md) adds a release-policy dependency: the current public listing exposes five built-in packages and direct pairing resolves known IDs independently of listing, subject to read-only probe admission. The [provisional first-cohort matrix](eh-g8-cfp1-public-directory-first-cohort-scope-v1.md) keeps `com.casimirbot.system.clock:1.0.0` excluded until C10 rights, generated-kit, persisted-metadata and clean external probe acceptance; if C10 remains selected, D12 must explicitly admit that exact row and its pairing/probe fixtures through a per-package policy. Built-in `approved` metadata does not substitute for C10 rights or installed acceptance. This does not change the separate Minecraft bootstrap route.

CFP-3 must reject the artifact if the 43-name export inventory changes, any deferred name/private import leaks, transitive types or runtime imports fail in a clean install, canonical schema parity fails, or an unreviewed file/notice is present. The TypeScript client currently requires `command_execution: "command_execution_not_enabled"` in heartbeat receipts, while the mock returns only `health`; the later fixture must be repaired and its heartbeat exercised. The existing conformance test also imports a Minecraft manifest fixture; the public test must use a standalone non-game fixture. Test wrong scope/identity, expiry, replay, version mismatch, unavailable endpoint and unknown package as typed denials. Record two-build hashes, extracted archive inventory, clean external TypeScript/Java compilation, independent pairing/probe and denial results. No public claim or release occurs before qualified rights review and this evidence.

The [CFP-3 developer-kit handoff](eh-g8-cfp3-public-connector-kit-v1.md) implements this selected direction only after stage admission. CFP-1 remains active (`specified`), CFP-2/3 blocked and G8 active.
