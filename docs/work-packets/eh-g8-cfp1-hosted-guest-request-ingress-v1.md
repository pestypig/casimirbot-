## First-cohort ingress decision for D12 review

Prefer **one authenticated domain browser request** as the first-cohort first-party guest baseline for the selected paid and trial action. The host keeps the signed app and local connector for the host-owned program; an invited guest can join and request the exact shared effect from the domain on a second client device. A guest needs their own verified CasimirBot account, room membership and consent for any actual data processing, but **does not need to install the program connector, obtain a GPT account or paid Codex subscription, supply an API key, or run a second reasoning runtime** to make that bounded request. This is a provisional D12 route choice, not an accepted current UI/API. The sponsor pays for eligible hosted capacity; the program owner, who may be the sponsor, alone pre-grants the exact effect. The request interface shows the program owner, subject, proposed effect and limit, whether the one-use grant is ready, and distinct admitted/native-result states. It offers no open-ended command or arbitrary action payload. The owner's explicit pre-grant and the guest's later request are separate operator choices; this path does not claim to run a new reasoning loop.

A guest who has their **own supported reasoning client** may instead request the same selected action through an independently qualified authenticated MCP profile. This is optional for guest participation. The supported MCP client/profile, exact tool catalog and result re-entry need their own installed acceptance; the first-party route may not be described as proof that every guest has Codex reasoning. Neither route receives the host's Codex session, credentials, model quota, task or subscription. Automatic delivery of room speech/text into an existing Codex task is a separate G8/PNA acceptance, not a hidden fallback for a guest without a model account.

The first-party request and optional MCP request must converge on **one server-owned admission and native-effect path**. The server derives the requester from the current account/session and room membership, and derives the target owner/source/subject from the current program binding. The caller cannot choose those authority fields by assertion. Before enqueue and again at the effect boundary, require current sponsor term/trial and resource capacity, the exact selected operation/context, current membership/role, a one-use owner-issued grant bound to this requester, subject, target, capability, count, connector epoch and expiry, and the native player/canvas authority. Reuse the CFP-3 delegated-grant and idempotency contract; a first-party request must never call the connector endpoint directly or skip the broker because it came from the UI. Reserve/settle sponsor PBT for platform work independently of the verified-successful-effect trial count. Keep owner stop/revoke and independent personal tools reachable when hosted capacity ends.

The first cohort may use one host-owned installed program with an invited guest on a second **client device**. That is narrower than a second guest-owned program/node, simultaneous players or generic cross-program federation. Freeze the actual domain page, API method/path and schema, session/cookie and CSRF rules, program visibility, accessible owner-grant/guest-request UI, notification method and exact result projection before CFP-3 dispatch. Neither a public page nor a signed-app deep link may inherit local connector or host reasoning credentials. If installed acceptance cannot provide the domain path, narrow the customer sentence to a separately proven guest-owned MCP path and state that client requirement plainly; do not silently impose it on every invited guest.

The [open-browser cost source audit](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-20-cfp1-open-browser-room-cost-source-audit-212.md) adds a first-party page lifecycle to freeze: active foreground use, dialog-closed/background presence, an unattended open tab, finite idle suspension and authenticated return. The current experimental room's continued background polling is only a stress comparator. The proposed guest page must either stop database-backed refresh/presence after a selected idle/lease boundary or include its worst sustained-open load in the D07 sponsor budget and global capacity case. Suspension must not extend or restart the trial, replenish PBT/effect capacity, silently replay a pending request or release a native effect without its separate stop rule. Room return rechecks current account/session, sponsor term/capacity, membership and program visibility; a new action separately rechecks its exact grant and revision. Freeze truthful pending/suspended/exhausted copy with the exact customer limit before D12.

For the first-cohort cost assay, **prefer finite, explicitly renewed room activity**: passive browser visibility and timer/heartbeat traffic do not renew the hosted activity lease. After the D07-selected idle boundary, the page presents a suspended state and stops routine database-backed refresh/presence work; an intentional authenticated return may request a new finite lease only after current sponsor capacity, account/session, membership and program-visibility checks. Any action grant is rechecked separately before an effect. A suspended page does not falsely show either person as live-present. Under the [provisional trial room-slot rule](eh-g8-cfp1-hosted-trial-lifecycle-decision-v1.md), suspension retains the one-room slot, while explicit closure frees that concurrent slot without resetting the sponsor's seven-day clock, effect count or cumulative PBT. A separately admitted native effect retains its own finite lease and stop/reconciliation rule; room suspension must neither abandon it silently nor create a second effect. Owner stop/revoke and safe native release remain reachable even while the room is suspended or sponsor PBT is exhausted. Measure the exact first-party implementation's request, compute, database and egress behavior before choosing a transport, idle interval or customer promise. If this direction cannot provide a useful seven-day/ten-effect trial, D07 must return to the owner with a costed alternative rather than silently inheriting the experimental room's background cadence.

The [five-minute lease candidate](eh-g8-cfp1-finite-room-lease-candidate-v1.md) fixes one **testable first assay input** and the deliberate-renewal, suspension and return states. It does not set the customer idle limit or waive PBT, per-resource bounds, installed usefulness, rights or qualified privacy/financial review.

## Verified browser account and return boundary

The [browser-identity source audit](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-20-cfp1-hosted-browser-identity-source-boundary-206.md) finds a current temporary `guest` room account and web sessions whose server expiry may be null. The selected paid/trial first-party path must resolve an **active verified Google/Auth0-linked internal account** for both sponsor and invited guest at room create/invite/join, program visibility, request, owner grant, result read and handoff. A temporary `guest` profile, local profile name, matching email, invite code, browser cookie alone or host payment is insufficient. Additional identity modes need their own verified ownership/recovery review before inclusion. Keep the current experimental guest-room behavior separate from the selected hosted room rather than globally deleting it in CFP-1.

Apply the [D02 finite browser-session proposal](eh-g8-cfp1-public-session-and-client-grant-lifecycle-decision-v1.md) to both people only after account/security approval. A cookie lifetime is not server expiry; every selected mutating route must resolve a current server session and enforce same-origin/CSRF protection appropriate to the final domain configuration. Signing out revokes that browser session and prevents new requests, grants and unreleased effects under it; it does not silently delete room membership, transfer sponsorship or claim that an already released native effect stopped. A finite released effect follows its own lease/stop evidence. On reauthentication, resolve the **same verified internal account** and current room/sponsor/member/program-visibility revisions; a previously queued request may only return its idempotent status, never replay or auto-submit an effect because sign-in succeeded. An action grant and its revision are rechecked before any new effect, not required merely to inspect the room. If the participant left, was removed or lost verified identity, access and pending effect admission remain denied even if a stale tab or invite code survives. A guest can inspect only the permitted result projection, not sponsor billing records, connector credentials or private program history.

## Acceptance and claim boundary

For the first-party baseline, CFP-3/4 must run a distinct host and guest account on two physical client devices with the host's installed connector and the guest's authenticated domain browser, **no guest GPT/Codex account, no guest model API key and no CasimirBot-funded provider key/session**. The guest first joins the eligible room under their own verified identity; the owner then grants one exact effect to that guest, who sees only the permitted program/effect and makes one exact request, and the connector reports one attributable native postcondition visible to both authorized views. Prove no effect from invite, media consent or pre-grant alone. Repeat with absent/expired grant, wrong requester/owner/target, stale source/lease/connector revision, exhausted sponsor PBT, expired trial/paid term, revoke, concurrent double-click/retry, restart and handoff. Race first-party and MCP submissions against the same one-use grant; at most one native effect occurs and accounting does not double settle. Denial, admitted request, action start and verified completion must have different typed receipts. The first-party result is a human-visible result; only the separately tested MCP path has tool-result re-entry into the guest's own reasoning turn.

Apply this ingress contract to either the conditional Minecraft action or a selected rights-cleared non-game replacement. For Minecraft, R-MC-01 still controls commercial eligibility; a UI path does not cure it. The [non-model room seam](eh-g8-cfp1-hosted-provider-spend-and-room-seam-v1.md) must prove zero platform-funded provider calls for the baseline path. D12 should freeze customer wording that promises invited guest participation without a GPT account only after the first-party route passes installed and external-user checks. Until then this is a **provisional CFP-1 product target**, not an available or approved public claim. It leaves G8 voice, federation and existing-task steering obligations open.
