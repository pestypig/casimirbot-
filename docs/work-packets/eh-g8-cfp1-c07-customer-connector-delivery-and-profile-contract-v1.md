# CFP-1 C07 customer connector delivery and profile contract v1

The owner-selected [C01–C15 component baseline](eh-g8-cfp1-first-customer-component-decision-sheet-v1.md) calls for **one signed EXE** and separately provisioned, reviewed Fabric assets. The [C15 direction](eh-g8-cfp1-customer-distribution-route-decision-v1.md) calls for a separate public binary-only GitHub Releases channel; that channel is not yet provisioned. The current [source audit](../evidence/eh-g8-codex-first-paid-product-delivery-v1/cfp-1/2026-09-20-cfp1-c07-customer-provisioning-source-gap-189.md) shows profile selection and lifecycle checks, not a customer acquisition flow or installed-byte trust. This packet turns the chosen boundary into an explicit **provisional first-cohort delivery rule** for rights and implementation review. It does not publish or install any JAR.

## Proposed first-cohort boundary

1. **CasimirBot-owned artifacts.** Release only the selected first-party player/sensor JARs, any necessary first-party configuration and a human-readable version/notice manifest as separately named C07 assets after C07/R-MC-01 disposition. Tie their immutable hashes to the **same frozen source/build cohort** and to a reviewed release tuple in the signed EXE or an equivalently authenticated manifest. A GitHub release asset URL, filename, mod version or server-reported catalog ID is never byte identity by itself. Do not bundle the standalone connector-core JAR as a third mod when the selected mod JARs already embed it; explicitly record both nested core archive hashes and metadata.
2. **Customer-owned prerequisites.** The customer supplies a valid Minecraft Java installation/account and accepts the game's/server's terms through the normal user-owned path. The accepted guide identifies the exact compatible Minecraft, Fabric Loader/API, server launcher and Java versions and their reviewed acquisition routes. CasimirBot does not package Minecraft game binaries, silently accept an EULA, scrape a user's game credentials, or treat a link to an upstream project as permission to rehost its binaries. If a future wizard downloads any third-party prerequisite, that exact URL/byte, notice, consent and commercial context needs a new C07/R-MC-01 disposition before enablement.
3. **Dedicated local profile.** The first accepted task uses one explicitly selected client/server profile with the approved placement and mod set. Prefer a dedicated isolated profile over copying an arbitrary existing `mods` directory. The current development utility's copy-equality receipt is diagnostic only; the future customer flow must verify each source/staged JAR against the **release allowlist** and reject unexpected evaluation-only mods in the accepted profile. Guard reparse/path substitution, verify staged bytes again immediately before launch and on restart/update, and link the actually loaded mod/manifest to the reviewed release tuple. An existing profile may be offered only if it passes the same identity and dependency checks without mutating unrelated user files.
4. **Free personal availability and hosted separation.** Once rights-cleared and accepted, the supported personal connector download and repair path is available without a CasimirBot subscription or trial. A hosted term can sponsor room coordination and separately owner-granted guest requests; neither download nor package possession supplies program authority. If R-MC-01 permits the free personal context but rejects the paid/trial guest action, retain only the reviewed personal claim and use the selected non-game fallback process for the commercial benefit. Do not put a payment check inside the Fabric mod or imply that the free download itself settles the paid relationship.
5. **Channel and rollback.** CFP-3.DISTRIBUTION must publish only the selected C07 assets and notices in a versioned, anonymously accessible channel coordinated with C15, without changing the source repository's visibility prematurely. Publish no asset until the signed EXE release tuple and manifest agree. Old supported connector profiles need a reviewed update/repair path and an explicit revocation rule; a stale JAR must fail selected effect admission. The separate desktop updater's old-feed migration remains governed by C15 and must not be inferred from JAR availability.

## Required frozen release tuple

Record source commit plus dirty/build-input hashes; signed EXE version/signature and expected manifest authority; player/sensor JAR names, hashes, mod IDs, versions and **placement**; each embedded core coordinate/version, extracted archive hash and metadata; approved Loader/API/Minecraft/Java versions and acquisition routes; server launcher identity and local EULA/loopback prerequisites; exact C07 asset URLs, checksums, notices and provenance; installed profile ID/path identity; selected bootstrap pairing, connector epoch, received action/observation manifests and admitted capability-catalog hash; and supported free/trial/paid contexts from qualified review. The [identity contract](eh-g8-cfp1-fabric-package-runtime-identity-contract-v1.md) controls the bootstrap/JAR/manifest mapping and separate directory-package decision. The [rights request](eh-g8-cfp1-component-rights-review-submission-v1.md) controls notice and license disposition. Do not substitute the `fabric-player:0.4.0` directory metadata for the P03 bootstrap tuple.

CFP-1 freezes this planned treatment and any reviewer-requested changes. CFP-2.ONBOARD/CAPABILITY proves the ordinary local setup and selected effect; CFP-3.SIGNING/DISTRIBUTION proves the assets/channel and installed byte provenance; CFP-3.SHARED-ACTION proves hosted grant isolation. CFP-4/5 repeat the accepted journey on the actual signed release and external user. A source test or local development profile cannot promote those claims. D07 cost, D11 qualified rights/privacy/financial returns and D12 customer-copy/component freeze still control CFP-1 exit.
